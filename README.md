# QOR

Рабочее пространство для кафе и пекарен: прогноз спроса, план приготовления и контроль списаний.

## Запуск

Нужен Node.js 18 или новее. Установка зависимостей не требуется.

```bash
npm start
```

Откройте http://localhost:3000. `PORT=8080 npm start` меняет порт.

Для статического хостинга публикуйте папку `dist` (без сборки). Все пути относительные, приложение совместимо с размещением в подпапке. HTTPS обеспечивает хостинг.

## Возможности

- Обзор списаний по себестоимости и сценарной экономии.
- Импорт CSV, валидация дат, чисел, дублей и полноты истории.
- Прогноз с недельной сезонностью и ограниченным трендом.
- Сравнение ошибки WAPE с baseline на последовательных отложенных днях.
- Резерв, сценарии спроса, экспорт CSV и печать плана кухни.
- История планов со статусами и удалением через подтверждение.
- Профиль заведения, резервная копия JSON и восстановление.
- Адаптивный интерфейс, помощь и быстрый старт.

## Данные

CSV UTF-8: `date,product,sold,prepared,price,cost`.

Минимум 35 последовательных дней на товар, одна строка на товар и дату, единая последняя дата для всех товаров. Цена и себестоимость товара должны быть постоянными. Продажи и приготовление — целые неотрицательные числа, продажи не выше приготовления. Максимум 100 товаров, 20 000 строк, 2 МБ. Пример скачивается в приложении.

Данные хранятся в localStorage браузера. Копия JSON переносит продажи, настройки и последние 120 планов между устройствами. Пользовательские данные не входят в репозиторий и не передаются серверу. Не используйте общее устройство для конфиденциальной информации. После очистки браузера данные без резервной копии восстановить нельзя.

## Прогноз и ограничения

Прогноз = 80% среднего спроса в тот же день недели за последние 28 дней + 20% общего среднего. Учитывается тренд последних 7 дней относительно предыдущих 14, ограниченный диапазоном 0.8–1.2. Это объяснимая статистическая модель, без LLM и внешних API.

Walk-forward проверка начинается после 28 дней: каждый прогноз видит только прошлую историю. Baseline — среднее предыдущих 7 дней. Экономия — оценка сокращения ожидаемых излишков, не обещание прибыли. Продажи при дефиците занижают реальный спрос. Для дат далеко за пределами истории модель не учитывает будущие изменения тренда.

Начальные данные синтетические и помечены как пример. Это однопользовательское приложение: без серверной базы, синхронизации устройств, авторизации и интеграции с POS. Хостинг Sites может дополнительно ограничивать доступ к опубликованному приложению.

## Структура

- `dist/index.html`, `dist/style.css`: интерфейс.
- `dist/model.js`: прогноз, проверка и пример данных.
- `dist/data.js`: CSV и проверка входных данных.
- `dist/app.js`: обзор, импорт, сценарии, график и экспорт.
- `dist/product.js`: настройки, история, резервные копии и навигация.
- `server.js`: локальный статический сервер.

## Минимальные проверки

```bash
npm test
```

Две проверки: прогноз на постоянном ряду и CSV с валидной историей/некорректными датами. Браузерная визуальная проверка в среде разработки не выполнялась.
